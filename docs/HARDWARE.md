## 引脚分配（8 引脚，全部用尽）

| 引脚 | 功能 | 方向 | 说明 |
|------|------|------|------|
| P3.0 | 未使用 | — | 悬空（UART RX），见下方说明 |
| P3.1 | 未使用 | — | 悬空（UART TX），见下方说明 |
| P3.2 | INT0 按键 | 输入 | 下降沿触发，唤醒 STOP 模式（中间操作开关） |
| P3.3 | ADC3 光照 | 模拟输入 | 接光传感器分压点，高阻抗 |
| P5.4 | I2C SDA | 开漏输出 | 连接 OLED SDA |
| P5.5 | I2C SCL | 开漏输出 | 连接 OLED SCL |
| VCC | 电源 | 输入 | 3.7V 锂电池直接供电给 MCU 与 OLED |
| GND | 地 | 输入 | 公共地 |

> **P3.0 / P3.1 保持悬空**。这两个脚是 STC 的 UART 兼 ISP 下载口，冷上电时引导程序会短暂监听它们。固件没有配置它们，保持上电默认的准双向弱上拉即可——弱上拉本身就能抑制干扰，不必额外加外部电阻，也不要改成推挽输出。
>
> 中间操作开关负责唤醒与模式切换，侧边独立开关控制手电筒，互不干扰。

## 光照传感器电路

```
        VCC (3.3V)
         │
       [LDR]         ← 光敏电阻在上臂（暗态 ~1MΩ，亮态 ~5KΩ）
         │
    ─────┤───── P3.3 (ADC3)
         │
       [100K]        ← 分压下臂（2026-10 由2K改为100K，降低待机漏电）
         │
        GND
```

- 暗态：LDR 阻值大，分压后 P3.3 电压低，ADC 值小
- 亮态：LDR 阻值小，P3.3 电压高，ADC 值大

### 阈值

光照判据直接用 ADC 原始值，不经过比率补偿：**原始读数 ≥ 1015** 视为光照充足，否则显示「请站在光里」并返回待机。

本机 ADC 是 10 位，满量程 1023。这一点用带隙通道可以交叉验证：带隙读数为 369 时，按 10 位算 `VDD = 1.19 × 1023 / 369 ≈ 3.30 V`，合理；按 12 位算则是 13.2 V，物理上不可能。强光读数又正好停在 1023（即 $2^{10}-1$），双重印证。

```
raw = 1023 × 100K / (100K + LDR)
```

| 状态 | 实测原始值 | 判定 |
|------|-----------|------|
| 完全遮挡 | 867 | 拦截 |
| 弱光 / 室内 | ≈950 | 拦截 |
| 强光直射 | 1023（饱和） | 放行 |

> **为什么不用比率补偿**：强光下分压已经顶到 1023 饱和，此时补偿值退化为 `comp = 1023?/bg`，只由带隙读数决定，bg 抖动几个 LSB 就会越过阈值，判据极不稳定——这正是此前阈值怎么调都卡不住的原因。而饱和点本身是相对 VDD 的，电池从 3.3 V 掉到 2.9 V 时强光照样读 1023，raw 判据天然与电池电压无关，还省掉了 32 位除法。
>
> **判据方向**：光敏电阻在上臂，光越强读数越大，比较方向是 `>=`。若方向写反，就会出现「越亮越提示请站在光里、遮住反而能选股」的镜像症状。
>
> 阈值由 `Sources/adc.c` 里的 `LIGHT_SUN_ADC` 控制，当前为 1015。取这么高是有意为之：室内、阴天、树荫都达不到接近饱和的读数，只有直射阳光才行。想放宽或收紧只改这一个数。

## 手电筒电路说明（独立开关控制）

原设计中 LED 与按键串联，导致两个问题：每次按键操作都会点亮 LED 增加功耗，且 LED 工作时的电流波动会干扰按键检测。因此将手电筒改为侧边独立开关供电：

```
 VCC (3.7V 锂电池)
         |
        [R_LED]  ← LED 限流电阻（建议 1kΩ，约 1~2 mA 驱动电流）
         |
        [LED]    ← 发光二极管（手电筒光源）
         |
        [SW]     ← 侧边独立开关（常开，手动控制）
         |
        GND
```

说明：手电筒与操作按钮完全解耦，各自独立工作。侧边开关直接控制 LED 通断，不经过 MCU，因此可以在任何状态下单独使用手电筒功能。

## 操作按钮电路说明（P3.2）

操作按钮仅用于 MCU 交互，电路简洁：

```
 P3.2 ────┬──── GND
         │
       [SW]     ← 中间操作按键（常开，按下接通）
```

不需要外部上拉电阻，MCU 内部上拉即可。

## OLED 连接

SSD1306 128×32 OLED 模块，I 2C 地址 `0x78`。

| OLED 引脚 | 连接 |
|-----------|------|
| VCC | 3.3V |
| GND | GND |
| SCL | P5.5（经上拉至 VCC） |
| SDA | P5.4（经上拉至 VCC） |

软件 I2C，无需硬件 I2C 外设。开漏输出 + 外部上拉（4.7KΩ 推荐）。

### 睡眠期间面板可能自己复位

STOP 期间 MCU 会把 `0x8D` 电荷泵关掉，但面板的 VDD 一直挂在电池上，没有断电。看起来它应该保持原样，实际上有个隐患：电池电压偏低时，I2C 上拉电阻和各引脚 ESD 二极管构成的漏电通路会把面板自己的复位电路慢慢拖到 POR 门限以下，面板就在睡眠期间悄悄复位了——寄存器和 GDDRAM 一起回出厂状态。

表现出来是三种偶发现象，都是「长时间休眠或电量偏低之后才出现，彻底断电重启就恢复」：

| 丢失的设置 | 出厂默认 | 现象 |
|---|---|---|
| `0xC8` COM 扫描方向 | `0xC0`（反向） | 画面上下颠倒 |
| `0x81` 对比度 `0xCF`、`0xD9` 预充 `0xF1` | `0x7F`、`0x22` | 颜色很淡 |
| `0xA8` 多路复用比 `0x1F`（32 路） | `0x3F`（64 路） | 一行乱码 |

所以固件在每次唤醒时都会把整张 OLED 命令表重发一遍，并重画显存内容（详见 `docs/ARCHITECTURE.md`）。这是软件侧的兜底；硬件上把电池保持在 3.0 V 以上、I2C 上拉不要过小，可以降低发生概率。



## 电源管理

| 状态 | 电流 | 说明 |
|------|------|------|
| 运行（OLED ON） | ~5mA | 显示 + MCU 运行 |
| STOP 待机 | ~5μA + 分压≈18~37μA | MCU 深度休眠，OLED 关闭；分压电流随环境光变化（上臂100K后） |
| 唤醒恢复 | ~10ms | INT0 中断唤醒，重新初始化 |
| 低电量（约<2.9V） | 0（关机） | 点亮屏幕显示电池耗尽图标约 1.2s 后关机 |

- 待机时 ADC 关闭、OLED 电荷泵关闭
- 所有 GPIO 恢复准双向口模式（最低漏电）
- 唤醒后先重发 OLED 配置并重画屏幕，再等按键释放进入正常流程

低电量阈值为 `BAT_LOW_ADC = 420`（带隙通道读数）。带隙读 369 对应 3.30 V，读数越大说明 VDD 越低，420 大约落在 2.9 V。电池满电、刚充满时读数在 369 附近，离 420 还有余量，不会误报。

## EEPROM

片上 EEPROM 双槽交替存储：

| 地址 | 内容 | 大小 |
|------|------|------|
| 0x0000 | 备份槽 A | 7 字节 |
| 0x0200 | 备份槽 B | 7 字节 |

存储格式（7 字节）：

| 偏移 | 长度 | 内容 |
|------|------|------|
| 0 | 1 | 校验字节 = 偏移 1~6 的异或，**最先写入** |
| 1~4 | 4 | 光功德，小端序 |
| 5 | 1 | 当前模式（0=选股，1=操盘） |
| 6 | 1 | 序号，每次保存 +1 |

每次保存只擦写其中一个槽（序号奇偶交替），另一个槽保留上一笔完整记录。启动时两槽都校验，取序号更新的那个。断电最坏只丢一次递增，绝不会读出半写数据。

## 供电方案：锂电池 + TP4057

### 为什么用锂电池？

作为一款要长期使用的设备，可充电锂电池比纽扣电池更实用：
- USB-C 充电，现代人手边都有线
- TP4057 充电管理芯片，安全可靠，成本仅 0.5 元
- 100mAh 锂电池，待机半年，日常使用绰绰有余

### 电池参数

| 参数 | 数值 |
|------|------|
| 类型 | 3.7V 锂聚合物电池 |
| 容量 | 100mAh |
| 充电接口 | USB Type-C |
| 充电管理 | TP4057（CC/CV） |
| 充满电压 | 4.2V |
| 放电截止 | 3.0V |
| 预计续航 | 半年以上（每天按 50 次） |

### TP4057 充电电路

```
USB-C VBUS (5V)
      │
      ▼
   ┌──────┐
   │TP4057│
   │      │──── CHRG (充电指示)
   │  OUT │──── STDBY (充满指示)
   └──┬───┘
      │
        3.7V ──┬── MCU + OLED (直接供电，请注意电压兼容性，详见下文)
                          │
                  锂电池
```

- TP4057：SOT-23-5 封装，充电电流可编程（默认 450mA）
- 充电时 CHRG 引脚拉低，可接 LED 指示
- 充满后 STDBY 引脚拉低，可接 LED 指示
- 输入端 0.1μF + 输出端 10μF 电容

注意：当前设计为电池直供 MCU 与 OLED。这意味着 MCU 与 OLED 将直接承受电池电压范围（约 4.2V 充满 → 3.0V 亏电）；请确保所用 MCU 与 OLED 模块在该电压范围内可靠工作，或在 PCB 版本中加入稳压或升降/降压转换方案以保证显示与 MCU 在全电量范围内的稳定性。

### 功耗分析

| 状态 | 电流 | 说明 |
|------|------|------|
| 运行（OLED ON） | ~5mA | 显示 + MCU 运行 |
| STOP 待机 | ~5μA + 分压≈18~37μA | MCU 深度休眠，OLED 关闭；分压电流随环境光变化（上臂100K后） |
| 唤醒恢复 | ~10ms | INT0 中断唤醒，重发 OLED 配置并重画 |
| 低电量（约<2.9V） | 0（关机） | 点亮屏幕显示电池耗尽图标约 1.2s 后关机 |
| 充电中 | ~450mA | TP4057 恒流充电 |

- 待机时 ADC 关闭、OLED 电荷泵关闭
- 所有 GPIO 恢复准双向口模式（最低漏电）
- 唤醒后先重发 OLED 配置并重画屏幕，再等按键释放进入正常流程
